# Deploying on Render (free plan)

This guide puts AEGIS online at a public `https://….onrender.com` address with Render's free plan. It runs as a **hosted demo**: one web service, demo accounts and the three DEMO FIXTURE cases. It is not a setup for real casework (see [Limits](#limits-of-the-free-plan)).

## Can it run next to my other Render project?

Yes. A free Render workspace can run several web services at once, so AEGIS can sit next to a project you already deployed. The limits that matter:

| Free-plan rule | What it means for you |
| --- | --- |
| **One free PostgreSQL database per workspace** | If your other project already uses the free database, Render will not create a second one. Use [Option B](#option-b-database-on-neon-works-next-to-any-other-project) below. This is the most likely reason Render asked you to cancel or remove something before deploying. |
| 750 free instance hours per month, shared by all free services | Services sleep after 15 minutes without visitors and use no hours while asleep, so two or three demo projects normally fit. If the hours run out, Render suspends every free service until the next month. |
| Free databases expire 30 days after creation | Render then gives 14 days to upgrade before deleting the database. A Neon database (Option B) does not expire. |

Check the current numbers on Render's [free plan page](https://render.com/docs/free) before relying on them; they change from time to time.

## What the Render deployment contains

[`render.yaml`](../../render.yaml) describes everything, so Render sets it up for you:

- **One Docker web service**, built from [`infrastructure/docker/render.Dockerfile`](../../infrastructure/docker/render.Dockerfile). The web workstation and the API run in the same container, and the browser only ever talks to one address.
- **Analyses run inside the web service** (`AEGIS_TASK_MODE=inline`), because Render has no free background workers. If a restart interrupts a job, the job resumes when the service starts again.
- **Evidence is stored in PostgreSQL** (`AEGIS_STORAGE_BACKEND=database`). Free services have no persistent disk and lose their files every time they sleep. In the database, evidence keeps its write-once guarantee and survives restarts.
- **No Redis.** Rate limits are kept in memory, and System Health reports Redis as "not configured".
- **Generated secrets.** `AEGIS_SECRET_KEY` and the reference watermark key are generated by Render; nobody needs to see them.
- **Demo data.** At start-up, the service loads the demo organisation and one account per role, all using a password you choose.

## Option A: everything on Render (simplest)

Use this if your workspace's free database is not in use yet.

1. Sign in at [dashboard.render.com](https://dashboard.render.com) with the GitHub account that owns this repository.
2. Click **New → Blueprint**, pick this repository and the `main` branch. Leave **Blueprint path** as `render.yaml`.
   You can also use the **Deploy to Render** button in the README.
3. Render lists the service `aegis` and the database `aegis-db`. For **AEGIS_DEMO_PASSWORD**, type a private password of at least 12 characters. Every demo account uses it.
4. Click **Apply**. The first build takes about 10–15 minutes. Follow it under the `aegis` service → **Logs**. The service is ready when the log shows `Demo organisation and DEMO FIXTURE cases are ready.`
5. Open the address shown at the top of the service page (for example `https://aegis-xxxx.onrender.com`), then sign in as `investigator@aegis.demo` with your password. The other accounts are `admin@`, `orgadmin@`, `analyst@`, `reviewer@`, `auditor@` and `researcher@aegis.demo`.

## Option B: database on Neon (works next to any other project)

Use this if Render says your workspace already has a free database. It is also the better choice if the demo must stay up longer than 30 days.

1. Create a free account at [neon.tech](https://neon.tech). Create a project in the **AWS Asia Pacific (Singapore)** region, close to Render's Singapore region.
2. On the project dashboard, click **Connect**. Turn **Connection pooling off**, then copy the connection string. It looks like `postgresql://user:password@ep-….ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.
3. In Render, click **New → Blueprint**, pick this repository and `main`. Set **Blueprint path** to:
   ```
   infrastructure/render/render-external-database.yaml
   ```
4. Fill in **AEGIS_DATABASE_URL** (the Neon string) and **AEGIS_DEMO_PASSWORD**, then click **Apply**.
5. Continue with steps 4 and 5 of Option A.

Any PostgreSQL 14+ database reachable over the internet works the same way (Supabase, a paid Render database, a college server). AEGIS accepts `postgres://` and `postgresql://` connection strings as given.

## Limits of the free plan

| Limit | Effect |
| --- | --- |
| Sleeps after 15 minutes without visitors | The first visit afterwards waits one to two minutes while the service starts. Nothing is lost: cases and evidence are in the database. |
| 0.1 CPU, 512 MB memory | Text and image analyses take seconds; audio and video can take minutes. Uploads are capped at 25 MB (`AEGIS_MAX_UPLOAD_MB`). |
| Render database: 1 GB, expires after 30 days | Upgrade it, or move to Option B before it expires. |
| No shell on free services | Administration happens in the web interface. Commands such as `create-admin` need a paid instance or a machine with database access. |

## Measured behaviour under free-plan limits

These numbers were measured before publishing, by running the image locally with Docker limited to the free plan's resources (`--cpus=0.1 --memory=512m`). The database ran in a separate container, as it does on Render. Render's own start-up time comes on top.

| Check | Result |
| --- | --- |
| First start on an empty database (migrations, roles, registry) until the public port answered | 69 s |
| Loading the demo organisation and the three DEMO FIXTURE cases, including their analyses | 49 s more, in the background |
| Restart after the container was deleted (files lost, as when Render puts the service to sleep) | 54 s; all 9 evidence items verified `OK`, audit chain `valid: true` |
| A video job killed mid-run by deleting the container | Resumed at start-up (attempt 2) and completed; the analysis step that had finished was not repeated |
| Peak memory (API, web, demo loading, browser test suite) | 308 MiB of 512 MiB |
| Browser test suite (`make test-e2e`) against the container | 3 of 3 passed |

## How this differs from a production deployment

The service runs with `AEGIS_ENVIRONMENT=hosted-demo`. AEGIS refuses in-process jobs when `AEGIS_ENVIRONMENT=production`, and a free plan cannot run the separate worker that production requires. Use the Render deployment to show and try the platform with synthetic data only. Never use it for real evidence or personal data. For real use, follow [deployment.md](deployment.md) or the [college server guide](college-server.md): a Celery worker, Redis, a persistent evidence store, backups and a legal, privacy and security review.

## Updating

Every push to `main` redeploys automatically. Changes that only touch Markdown files, screenshots or browser tests are skipped, which saves Render's monthly build minutes. To change a setting, open the service → **Environment**, edit the value and save. Render restarts the service with the new value.

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Log says `Demo data not loaded: set AEGIS_DEMO_PASSWORD…` | Set **AEGIS_DEMO_PASSWORD** under **Environment** to at least 12 characters (the public default is refused), then save. |
| Changing **AEGIS_DEMO_PASSWORD** has no effect | The password is applied only when the demo accounts are first created. To start over, delete and recreate the database (this erases all data). |
| `502` or "service unavailable" on the first visit | The service is waking up or still running migrations. Wait a minute and reload. |
| Build fails with "no space" or a timeout | Click **Manual Deploy → Clear build cache & deploy**. |
| Blueprint creation fails because of the database | Your workspace's free database is taken: use Option B. |
| A job stays *running* | It is probably a video on 0.1 CPU. Give it a few minutes, or cancel it from the case page. A job interrupted by a restart resumes when the service starts. |
